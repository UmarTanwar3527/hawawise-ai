# Air Guardian and the Daily Air Brief (Day 2)

Evidence-grounded AI on top of the stored Jaipur air-quality data. The model never fetches data itself, never calculates an AQI and never writes evidence.

## How a question is answered

```text
Browser ── POST /api/ai/chat {message, history (signed)} ──► route
  validate (Zod, size, rate limit) ─► runGuardian (orchestrator)
    loop ≤ 5 turns, ≤ 8 tool calls, Gemini function calling (mode ANY):
      model requests an allowlisted tool ─► server validates args (Zod) ─► runs it
      on the existing service layer ─► result returned as functionResponse (data only)
    model calls submit_answer ─► server checks:
      • shape (Zod)            • reply language (server-detected; one retry)
      • grounding: every AQI / concentration figure must match retrieved data
        or curated reference figures (one retry, then a safe answer with no numbers)
  evidence + tool activity + staleness warnings are built by the server
  from the actual tool results ─► response + HMAC signature for the answer
```

### Tools (`src/features/ai-guardian/tools/tools.ts`)

| Tool | Reads | Notes |
| --- | --- | --- |
| `get_current_air_quality` | `getAreaAirQuality` (cached) | Nearest fresh station + calculated CPCB AQI, modelled estimate, freshness. Unverified ppb/ppm values are passed without their numbers. |
| `get_air_quality_forecast` | `getAreaForecast` (cached) | Daily PM2.5/PM10 mean, min and max. Labelled forecast, with the model-bias note. No AQI. |
| `compare_neighbourhoods` | `getStationsOverview`, `getStationsLatestPollutant` | All stations by AQI, PM2.5 or PM10. Stale stations flagged. Optional area → nearest-station mapping. |
| `get_air_quality_trend` | `getStationHistory` | Hourly measured PM2.5/PM10 at the area's station, with completeness and summary statistics. |
| `search_knowledge` | `rag/knowledge-base.ts` | Curated WHO 2021, India NAAQS 2009, CPCB categories and method, WHO health effects, and Hawa AI methodology. Links only where verified. |
| `submit_answer` | — | Final structured answer. |

There is no tool for arbitrary SQL, URLs or code.

### Prompt

`prompts/air-guardian.v1.ts` (`air-guardian/v1`). Change the version with any edit.

## Daily Air Brief

- Generated by `GET /api/cron/brief` (Bearer `CRON_SECRET`), which the hourly GitHub workflow calls after ingestion. **It is never generated on page load.**
- It uses the same tools as the chat, reading uncached data, in one model call with `submit_brief`, and the same grounding check.
- **Regenerated only when** the data signature changes (IST day plus each fresh station's category), or the last brief is older than 3 hours. It is **skipped** when fewer than 2 stations have fresh data.
- Stored in `ai_daily_briefs` (public read, server write, 7-day retention). The dashboard reads the latest brief through the cache. With no brief, it shows an empty state rather than generated text.

## Configuration

| Variable | Default | Purpose |
| --- | --- | --- |
| `GEMINI_API_KEY` | — | Required for AI features. Server only. |
| `GEMINI_MODEL` | `gemini-3.5-flash-lite` | Primary model. |
| `GEMINI_FALLBACK_MODELS` | `gemini-3.1-flash-lite,gemini-3.5-flash` | Tried in order on quota (429) or capacity (5xx) errors. |
| `GEMINI_THINKING_LEVEL` | `minimal` | Lower is faster. Grounding is enforced server-side regardless. |

Per call: 25 s timeout, 1 retry on timeouts and 5xx (no immediate retry on 429), and a cap of 1,500 output tokens.

## Measured behaviour (2026-11-25, local, live data)

- **`gemini-3.5-flash` at low thinking:** 34–78 s per answer, and the free-tier quota was **20 requests/day per model**. It was exhausted during testing.
- **`gemini-3.5-flash-lite` at minimal thinking:**
  - About 2–11 s per answer.
  - All six acceptance prompts were grounded, with correct sources and IST times.
  - It refused to invent a number.
  - It answered the Hinglish question in Hindi.
- **Quota:** each answer uses 2–5 model requests. Check your project's free-tier limits in Google AI Studio (Rate limits) before a demo.

## Security

- Gemini is called only from server code (`src/lib/gemini/client.ts`, `server-only`).
- **Input limits:** 1,000-character questions, 32 KB bodies and 12 history items, all Zod-validated.
- **Rate limits:** 8 per minute and 60 per day per IP, plus 1,500 per day per server instance. The counts are **in memory and per instance**; add an edge, WAF or shared-store limit before high traffic.
- **History signing:** conversations are not stored (no accounts). Assistant turns sent back by the browser must carry the server's HMAC signature. Forged or unsigned turns are dropped.
- **Prompt injection:** tool output is passed only as function responses. The system prompt says data is not instructions, and the grounding check rejects invented figures whatever the instructions.
- **Rendering:** a minimal Markdown renderer that emits React text only (no HTML, no model-supplied links). Evidence links come from the curated list only.
- **Logs:** they contain error kinds and rejected figures only; never prompts, keys or responses.

## Not done or limitations

- **No conversation persistence:** `ai_conversations`, `ai_messages` and `ai_evidence` are unused until authentication returns. Chats live in the browser tab (sessionStorage).
- **No streaming:** the UI shows tool activity after the answer, not live.
- **Grounding scope:** it checks AQI values and concentrations with units. Other numbers (distances, percentages, times) are not checked. Allowed figures come from **numeric fields** of tool results (`collectDataNumbers`) plus the curated knowledge text; digits inside strings such as timestamps (`2026-11-25`) or station names (`Sector-12`) do not count, since they would otherwise let invented values like "25 µg/m³" pass (fixed 2026-11-25).
- **Retrieval:** knowledge retrieval is keyword-based over 6 curated items. The `KnowledgeItem` shape is ready for a vector store later.
